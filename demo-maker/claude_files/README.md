# ProjectTrack Cinematic Ad — Build Instructions

## 0. Project layout (what you'll end up with)

```
projecttrack-ad/
├── ProjectTrack_Epic_Demo.mp4      ← your raw 102s recording (place here)
├── mac_frame.png                   ← your transparent mockup (place here)
├── build_assets.py
├── timings.json                    ← generated by the script
├── package.json
├── public/
│   └── assets/                     ← generated: clip_1..6.mp4, voice_1..6.mp3, mac_frame.png
└── src/
    ├── Root.tsx
    ├── AppleAd.tsx
    └── index.ts
```

## 1. Create the Remotion project

```bash
npx create-video@latest projecttrack-ad --blank
cd projecttrack-ad
```

## 2. Install Python deps (system-wide or in a venv)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install edge-tts
```

Make sure `ffmpeg` and `ffprobe` are installed and on your PATH:

```bash
ffmpeg -version
ffprobe -version
```

## 3. Drop in your raw assets

Copy these two files into the **project root** (same level as `package.json`):

```bash
cp /path/to/ProjectTrack_Epic_Demo.mp4 .
cp /path/to/mac_frame.png .
```

## 4. Add build_assets.py and run it

Copy `build_assets.py` into the project root, then:

```bash
python build_assets.py
```

This will:
- Slice 6 exact 10s chunks into `public/assets/clip_1.mp4` … `clip_6.mp4`
- Generate 6 voiceovers into `public/assets/voice_1.mp3` … `voice_6.mp3`
- Copy `mac_frame.png` into `public/assets/`
- Write `timings.json` at the project root with every scene's `startFrame`
  and `durationInFrames`, computed with zero gaps and zero overlaps

You'll see output like:

```
[1/6] Intro
    → slicing @ 00:00:00 for 10s ...
    → generating voiceover: "Managing college projects shouldn't feel like chaos. Meet ProjectTrack."
    → VO duration: 4180ms  |  scene length: 137f (4.57s)  |  startFrame: 0
...
✅ Done. Total video length: 812 frames (~27.1s) across 6 scenes.
```

## 5. Add the Remotion components

Copy `Root.tsx` and `AppleAd.tsx` into `src/`, overwriting the template's
`Root.tsx`. Confirm `src/index.ts` looks like this (create-video scaffolds
it by default):

```ts
import { registerRoot } from "remotion";
import { RemotionRoot } from "./Root";

registerRoot(RemotionRoot);
```

Confirm `tsconfig.json` has:

```json
{
  "compilerOptions": {
    "resolveJsonModule": true
  }
}
```

(Remotion's default templates already include this — just double-check.)

## 6. Preview in the Remotion Studio

```bash
npx remotion studio
```

Open the `ProjectTrackAd` composition. You should see all 6 scenes
back-to-back, each with its own voiceover, kinetic headline, and Ken
Burns-zoomed MacBook — matching your actual screen recording, not a
freeze-frame or black screen.

**If the video doesn't align with the mockup bezel:** open `AppleAd.tsx`
and tweak the four `SCREEN_BOX` percentages (`top`, `left`, `width`,
`height`) until the screen recording sits exactly inside your
`mac_frame.png`'s laptop screen.

## 7. Render the final MP4

```bash
npx remotion render ProjectTrackAd out/ProjectTrack-Ad.mp4 --codec=h264
```

For faster iteration while tuning timing/design, render a low-res draft:

```bash
npx remotion render ProjectTrackAd out/draft.mp4 --scale=0.5 --codec=h264
```

## 8. Re-running after script/voice changes

If you edit the `SCENES` array in `build_assets.py` (different script
lines, different voice, different timestamps), just re-run:

```bash
python build_assets.py
```

Everything downstream — `timings.json`, `Root.tsx`'s `durationInFrames`,
every scene's `startFrame` — recomputes automatically. Nothing in the
React code needs to change.

## Notes on the two original bugs

- **Black screens with `startFrom`**: fixed by never touching the big
  102s file at render time. `build_assets.py` physically slices it once
  into six independent files; Remotion plays those small files with
  `OffthreadVideo` (ffmpeg-based frame extraction) instead of decoding
  into a giant `<video>` element and seeking around inside it.
- **VO mismatch/overlap**: fixed by making duration flow one direction —
  TTS audio length → `ffprobe` measurement → scene `durationInFrames` →
  cumulative `startFrame`. Remotion never hardcodes a frame count; it
  reads `timings.json`. Each clip's `playbackRate` is computed as
  `nativeClipFrames / sceneDurationFrames`, so even if a voiceover runs
  slightly longer or shorter than the source clip's natural 10s, the
  footage subtly stretches or compresses to land exactly on the last
  frame of the scene, in sync with the VO's last word.
